Give your agents company knowledge they can reason over.

SIGN is a plain-text notation for the definitions, rules and relationships your agents work from. It is typed, so an agent can tell a rule from a property. It is compact, so a whole index fits in a system prompt. And every fact records where it came from.

Why SIGN exists

The common formats were built for a different reader.

JSON was built for programs, markdown for people, and RDF for semantic-web tooling. SIGN was designed with an agent's context window as the reader.

Summary of the comparison in the SIGN specification README.
ApproachWhere it falls short for agents
JSONMuch of each payload is brackets, quotes and keys. It has no way to say how two things relate, what can be inferred, or what is forbidden.
MarkdownCompact, but untyped. An agent cannot tell a rule from a property or a constraint.
RDF and OWLRigorous, but the syntax is heavy, the toolchain is large, and models have seen little of it in training.
Prompt textFast to write, but unversioned, hard to audit, and copied from prompt to prompt.
SIGNTyped blocks for definitions, relationships, rules and constraints; provenance on every fact; versions and review dates on every document.
What a SIGN document holds

Six kinds of content, each in its own typed block.

Structure

Entities, definitions, properties and the taxonomy they sit in.

Relationships

Typed edges between documents and entities, with every predicate defined in a vocabulary block.

Inference rules

Governed rules that derive new facts, each with a condition, a result, a confidence and a source.

Constraints

Rules an agent must enforce: what is mutually exclusive, what is required, what is forbidden.

Provenance

Whether each fact was asserted or inferred, where it came from, and how it was validated.

Governance

Status, version, review cycle and owner on every document, so agents skip retired rules.

Two-layer delivery

Agents load a short index, then fetch only the documents they need.

Layer 1 is an index of every document: its ID, status, links and a one-line summary. It goes into every system prompt. Layer 2 is the full text of each document, which the agent retrieves by ID when a task needs it.
